# Architecture

LightCode is a set of mechanisms that plug into coding agents ("hosts")
at well-defined seams. The host owns the agent loop, sessions, tools, models
and sandbox; LightCode never re-implements them.

## Layers

```
adapters      @lightcode/pi · adapters/codex · (DeepSeek Harness 0.2.x, planned)
              translate host events into port calls; install, configure, show receipts
mechanisms    @lightcode/mechanisms — Economy engine, command normalization, receipts
protocol      @lightcode/protocol — capabilities, host profiles, negotiation, journal schema
core          @lightcode/core — filters, source maps, admission, normalization (pure)
store         @lightcode/store — journal, original store, configuration (local files)
cli           @lightcode/cli — lc run / hook / report / doctor / filters / show / gc
```

`core` has no host dependency and no I/O. The same input produces the same
bytes in every adapter; `conformance/economy` holds the corpus that enforces
it, generated by the research runtime the filters come from.

## Capabilities and negotiation

Adapters declare what their host offers (`HOST_PROFILES`); each mechanism
declares what it needs (`MechanismSpec`). `negotiate` picks the strongest
supported mode — `apply`, `observe` or `off` — and records why. User
configuration can lower a mode, never raise it. No mechanism requires a host
patch.

| Capability | pi 1.x | Codex 0.162 | DeepSeek Harness 0.2 |
|---|---|---|---|
| replace a tool result before the model sees it | `tool_result` | — | `tools/post-execute` |
| …while the host session keeps the original | `turn_end` → `context_edit` | — | — |
| rewrite tool arguments before execution | `tool_call` (mutate input) | `PreToolUse` `updatedInput` | `tools/pre-execute` |
| run shell commands through `lc run` | — | ✓ (via `PreToolUse`) | — |
| supply the compaction summary | `session_before_compact` | — (shape only) | compaction provider |
| register model-callable tools | `registerTool` | MCP server | `tools.register` |
| read sessions and per-request usage | session JSONL `usage` | rollout `token_count` | session log |

## Token Economy

1. **Normalize** (optional, before execution): presentation-only flags that
   make output recognizable — `-n -H` for plain `grep`/`rg`, `--no-color` for
   `git diff`, `--color=no` for `pytest`. Patterns, paths, test selection and
   diagnostics are never changed. The model's history keeps its own command.
2. **Decide** (`decideShellProjection`): the command must be literal or an
   inspectable search/listing pipeline; truncated or interrupted output
   passes; stdout goes through the filter set; stderr only through filters
   with a proven stderr contract (Cargo reports, exact duplicate folding).
3. **Admit**: the projection must be strictly smaller in UTF-8 bytes and save
   at least `minimumSavedTokens` (≥ 1).
4. **Save, journal, deliver**: the original and the source map go to the
   private store, the decision to the journal, and only then does the
   projection reach the model. Any failure delivers the original.
5. **Pin**: the filter policy is captured once per session; a delivered
   projection is never re-rendered.

How the projection reaches the model differs by host:

- **pi** — prepared at `tool_result` (which returns nothing, so pi records
  the original), committed at `turn_end` as a `context_edit` entry that pi
  applies from the next request on. The model never reads the original.
- **Codex** — the `PreToolUse` hook rewrites the command to
  `lc run --host codex --session S --call C -c '<command>'`. `lc run`
  executes it with the user's shell, keeps exit status and signals, and
  prints the projection. Codex's own output budget then applies to a smaller
  text.
- **Any agent** — `lc run` directly.

pi and Codex merge stdout and stderr into one text; on those hosts filters
see the merged stream, and the journal records `streams: "merged"`.
`lc run` keeps the streams apart.

## Journal and store

- `~/.lightcode/journal/<host>/<session>.jsonl` — one record per decision
  (`economy/decision`) or rewrite (`economy/command-rewrite`), anchored to
  the host's session and tool-call IDs. Outcomes: `projected`, `previewed`,
  `passed` (with the reason and, for misses, why no filter applied) and
  `failed-open`.
- `~/.lightcode/artifacts/` — content-addressed originals and source maps,
  mode 0600, pruned after `retentionDays`.
- LightCode never writes into host session formats it does not own, so no
  host needs a patch and host upgrades cannot break old sessions.

`lc report` folds the journal into savings per filter and the most frequent
uncovered commands — the list of filters worth writing next.

## Invariants (tested)

- Byte-identical projections to the conformance corpus.
- Exit codes and signals pass through `lc run`; binary output is untouched.
- A projection is never larger than the original in bytes or tokens.
- Copied spans of every source map match the original exactly.
- Disabled, observe and failure paths deliver the original byte-for-byte.
